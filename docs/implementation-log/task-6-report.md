## Deviation from brief: SiteEntity column mapping bug (fixed)

The brief's `TenancyQueryService` code was correct as given and required **zero changes**. But running it
against the real H2-seeded DB (rather than just compiling) surfaced a latent bug in `SiteEntity`
(`com.nextstep.infra.persistence.SiteEntity`, from Task 5) that made every `SiteEntity` load fail with:

```
org.h2.jdbc.JdbcSQLSyntaxErrorException: Column "SE1_0.ORIGINALX" not found
```

**Root cause**: `SiteEntity.originalX` / `originalY` had no `@Column` annotation. Spring Boot's default
physical naming strategy (`SpringPhysicalNamingStrategy`) inserts an underscore before an uppercase letter
only when that uppercase letter is *also* followed by a lowercase letter (its `addUnderscores` loop requires
`lower, upper, lower` in sequence and stops one character short of the string end). Because `X`/`Y` are the
last character of the field name, no underscore ever gets inserted, so `originalX` → `originalx` instead of
the expected `original_x`. `schema.sql` (from Task 2) defines the columns as `original_x` / `original_y`, so
every `SELECT * FROM site` generated by Hibernate broke at the SQL layer — this wasn't specific to
`TenancyQueryService`, it would have broken `SiteJpaRepository.findById`/`findAll` for anyone.

**Fix**: added explicit `@Column(name = "original_x")` / `@Column(name = "original_y")` to those two fields
in `server/src/main/java/com/nextstep/infra/persistence/SiteEntity.java`. Minimal, surgical — no other fields
touched, no schema change.

This was pre-existing broken code from Task 5, not something introduced by this task's `TenancyQueryService`
code. Per the brief's authorization ("이 태스크는 여러 계층을 연결하는 통합 지점이라... 판단으로 고쳐도 된다"),
fixed it directly and documented it here rather than stopping.

No other deviations. Everything else in the brief (test file, service file, package structure, commit
message for the feature commit) was used as-is.
