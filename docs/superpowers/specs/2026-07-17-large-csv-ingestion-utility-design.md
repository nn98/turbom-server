# 대용량 전국 CSV 처리 유틸 확장 설계

**Date:** 2026-07-17
**Status:** Approved

---

## 문제

`data/식품_일반음식점.csv`(660MB, 2,286,490행)를 계기로 확인됨: 앞으로 추가될 원본 CSV는 성남시 단위로 미리 잘려서 오지 않고, **전국 단위 원본**으로 올 수 있다. 기존 `server/scripts/parse_licensed_records.py`(2026-07-17 세션 초반 구현, 8,547행짜리 성남시 단독 파일 기준)는 이런 파일을 다루는 데 3가지가 부족하다:

1. **파일명 규칙**: `대분류_소분류_지역.csv`(3세그먼트) 고정 가정 — 전국판은 지역 세그먼트가 없어(`식품_일반음식점.csv`, 2세그먼트) 현재 정규식이 거부한다.
2. **스코프 필터 없음**: 230만 행 중 성남시는 30,472행(1.3%)뿐. 현재 로직은 필터 없이 매 행마다 지번주소 파싱을 시도하므로 불필요한 연산이 크다.
3. **중복 적재 위험**: `개방자치단체코드=='3780000'`(성남시)로 걸러진 30,472행을 실측한 결과, 관리번호 체계(`3790000-101-YYYY-NNNNN`)가 **이미 적재된 '식품'/'일반음식점' 10,211건과 동일**함이 확인됨 — 이 파일은 신규 데이터가 아니라 기존 적재분의 최신 스냅샷일 가능성이 높다. 관리번호 기준 중복 제거 없이 그대로 적재하면 대량 중복이 생긴다.

이 문서는 이 CSV **한 건을 적재하는 게 목적이 아니라**, 앞으로도 이런 전국 단위 대용량 원본이 올 때마다 재사용할 수 있는 유틸 확장이 목적이다.

## 설계

### 1. 파일명 규칙 완화

```
기존: ^(?P<category>[^_]+)_(?P<sub_category>[^_]+)_[^_]+\.csv$   (지역 세그먼트 필수)
변경: ^(?P<category>[^_]+)_(?P<sub_category>[^_]+)(_[^_]+)?\.csv$  (지역 세그먼트 옵션)
```
지역 세그먼트는 캡처하지 않으므로(대분류/소분류 유도에만 쓰고 지역명 자체는 안 씀) 있든 없든 동작 동일.

### 2. 개방자치단체코드 사전 필터

```
SEONGNAM_GOV_CODE = "3780000"
```
CSV 각 행에서 `개방자치단체코드 != SEONGNAM_GOV_CODE`면 지번주소 파싱을 시도조차 하지 않고 즉시 스킵(`NOT_SEONGNAM` 사유 카운트). 실측: 이 필터 하나로 230만 행 중 99%가 초반에 걸러짐. 기존 `REGION_FILTER`(법정동명 문자열 매칭, PNU 조립 단계)는 그대로 유지 — 이건 실제 지번 파싱의 정확성을 담보하는 별개 안전장치라 중복이지만 둘 다 필요(전자는 속도, 후자는 정확성).

### 3. 관리번호 기준 중복 제거

```
새 함수: load_existing_license_nos(data_dir: str) -> set[str]
```
- `data_dir`(`server/src/main/resources/data/`) 안의 기존 `licensed-business-records-*.sql` 전부를 정규식(`'([0-9]{7}-[0-9]{3}-[0-9]{4}-[0-9]{5})'` 형태, 관리번호가 5번째 컬럼값)으로 스캔해 license_no 집합을 만든다.
- 새 행 처리 전 `관리번호`가 이 집합에 있으면 스킵(`DUPLICATE_LICENSE_NO` 사유 카운트).
- 이 스캔은 스크립트 실행 시작 시 1회만 수행(현재 46개+ SQL 청크 전체를 정규식으로 훑는 것도 초 단위로 끝남 — 텍스트 스캔이라 가벼움).

### 4. 스트리밍은 이미 충족됨

`csv.DictReader`는 원래 한 줄씩 lazy하게 읽는다 — 660MB 파일이라도 전체를 메모리에 올리지 않는다. 필터를 통과한 행만 `rows: list[str]`에 누적되므로(성남시 사전 필터 이후 이미 1% 이하로 줄어든 상태), 메모리 문제 없음. 별도의 스트리밍 아키텍처 변경은 불필요 — 기존 구조가 이미 대응 가능하다는 게 실측으로 확인됨(230만 행 스캔에 16초, 필터 로직만 추가하면 충분).

## 테스트 시나리오

1. **지역 세그먼트 없는 파일명**: `식품_일반음식점.csv` → category="식품", sub_category="일반음식점"
2. **지역 세그먼트 있는 파일명(회귀)**: `기타_담배소매업_경기성남시.csv` → 기존과 동일하게 동작
3. **성남시 아닌 행 사전 스킵**: `개방자치단체코드='1100000'`(서울) 행 → PNU 파싱 시도 없이 `NOT_SEONGNAM`으로 즉시 스킵
4. **중복 관리번호 스킵**: 기존 SQL 청크에 이미 있는 `관리번호`를 가진 신규 행 → `DUPLICATE_LICENSE_NO`로 스킵
5. **신규 관리번호는 정상 처리**: 기존에 없는 관리번호 → 기존 로직대로 PNU 계산 후 INSERT 행 생성

## 한계 및 후속 작업

| 항목 | 상태 |
|---|---|
| 실제 `식품_일반음식점.csv` 적재 실행 | 이번 스코프 아님 — 유틸 완성 후 별도 요청 시 실행 |
| 관리번호가 없거나 형식이 다른 미래 원본 | 이번 정규식(`\d{7}-\d{3}-\d{4}-\d{5}`)은 지금까지 본 모든 파일의 공통 형식 — 다른 형식이 오면 재검토 필요 |
| 관리번호 기준 중복이 "같은 레코드의 최신판"인지 "우연히 같은 번호"인지는 미검증 | 관리번호는 지자체+연도+일련번호 조합이라 재사용 가능성은 낮다고 가정(성남시 자체 확인 결과와 일치) — 실행 시 스킵 카운트가 비정상적으로 크면 재검토 |
