# 원본 인허가 CSV → 서비스용 레코드 파싱 유틸 설계

**Date:** 2026-07-17
**Status:** Approved

---

## 문제

`data/기타_담배소매업_경기성남시.csv`가 새로 추가됐다. 향후에도 이런 "지방행정 인허가데이터개방 표준" 계열 원본이 계속 추가될 것으로 예상되는데, 기존 파이프라인(`spec/인허가-데이터-필드명세-v4.md`가 가정하는 19컬럼·PNU-포함 구조)과 컬럼 구성이 완전히 다르다.

### 실제 구조 확인 (`기타_담배소매업_경기성남시.csv`, 8547행, cp949)

24컬럼: `개방자치단체코드,관리번호,인허가일자,인허가취소일자,영업상태명,폐업일자,휴업시작일자,휴업종료일자,소재지우편번호,도로명우편번호,사업장명,데이터갱신구분,데이터갱신시점,도로명주소,민원종류명,상세영업상태명,상세영업상태코드,영업상태코드,전화번호,좌표정보(X),좌표정보(Y),지번주소,지정일자,최종수정시점`

기존 구조와의 핵심 차이:

| 항목 | 기존 가정(19컬럼) | 이 파일 |
|---|---|---|
| PNU | 컬럼으로 직접 옴, 유도 불필요 | **컬럼 없음. 최초로 지번주소에서 직접 계산 필요** |
| 대분류/소분류 | 컬럼 2개, 항상 채워짐 | **컬럼 없음.** `민원종류명`은 8547건 중 대부분 공백 |
| 상태코드 체계 | 기존 seed 데이터 코드(`24`/`직권폐업` 등) | 이 파일 전용 코드(`0`/`2` 등, 파일마다 다름) |
| 지번주소 품질 | 기준 없음(예시 20행만 검증됨) | 57.4%가 "…호"로 끝나는 구식 표기 |
| 좌표 | 결측 0%(10건 표본) | 85.2% 채움 (완전하진 않음) |

### 검토했다가 기각한 소스: `data/인허가업소정보.csv`

카탈로그(`행정안전부_인허가업소정보`, data.go.kr 15153260)의 100행짜리 전국 미리보기 샘플. 실제 컬럼은 `SALS_UNQ_SE_NO_LCPMT_NO, TPBIZ_NM, BUES_NM, RPRSV_NM, TELNO, PRMSN_YMD, ADDR` 7개뿐 — **폐업일자·지번주소·좌표가 전부 없다.** 개폐업 타임라인(제품 핵심)과 PNU 키(지번 기반) 둘 다 이 소스로는 구현 불가. 스펙을 이쪽에 맞추는 안은 기각 — 이 소스는 API 필드 스키마 문서화 용도로만 참고하고 적재 대상에서 제외한다.

### 지번주소 "호" 표기 — 마스킹이 아니라 구식 표기였음

`...호`로 끝나는 4907건(57.4%) 중 95.8%(4653건 중 4457건)가 `숫자(-숫자)?호` 형태로, 오래된 데이터(1974~1990년대 다수)가 "번지" 대신 "호"를 지번 종결어로 쓴 것으로 확인됨(`수진동 4355호` vs `수진동 4224번지` — 구조 동일, 종결어만 다름). 연도별 malformed 비율은 완만히 감소할 뿐 뚜렷한 컷오프가 없어 날짜 기준 필터링은 부적절 — 대신 파서가 "호"와 "번지"를 동일하게 지번 종결어로 인식하도록 설계한다. 진짜 잡텍스트(괄호 안 부가정보, 건물명 등)는 4.2%(196건)뿐.

### PNU 유도 — 이 프로젝트에 없던 신규 기능

`spec/backend-spec.md:88`, `spec/인허가-데이터-필드명세-v4.md:16,53` 전부 "PNU 100% 채움 확인, 유도 불필요"로 명시 — 지금까지 로드된 모든 데이터가 원본에 PNU를 이미 포함하고 있었기 때문에, **지번주소 텍스트에서 PNU를 실제로 계산하는 로직은 이 코드베이스에 한 번도 존재한 적이 없다.** 이번이 최초 구현.

법정동코드 전국 45,958건(코드+명칭+존재여부)을 커뮤니티 미러(FinanceData gist, code.go.kr 공식 API는 이 개발환경 네트워크 차단 + 서비스키 미보유로 직접 조회 불가)로 확보해 검증함 — `4113110800`(경기도 성남시 수정구 창곡동, "존재")이 기존에 이미 적재된 실 PNU(`4113110800105090000` 등)의 앞 10자리와 정확히 일치함을 확인. 성남시 44개 동만 있으면 이번 파일은 충분하지만, 향후 타 지역 확장을 대비해 **전국 단위로 저장**하기로 함(사용자 확정).

## 설계

### 구성 요소 (`server/scripts/` 신설)

| 파일 | 역할 |
|---|---|
| `legaldong_codes.csv` | 전국 법정동코드 45,958건(코드, 명칭, 존재여부). 폐지된 코드는 매칭 후보에서 제외 |
| `parse_licensed_records.py` | 파싱 스크립트 본체 |
| `README.md` | 사용법, 파일명 컨벤션, 다음 파일 추가 시 체크리스트 |

### 파싱 파이프라인

```
1. 파일명에서 대분류/소분류 유도
   {대분류}_{소분류}_{지역}.csv 컨벤션 (data_uncleaning/ 기존 파일들과 동일 규칙)
   "기타_담배소매업_경기성남시.csv" → category="기타", subCategory="담배소매업"

2. CSV 읽기 (cp949)

3. 지번주소 파싱
   정규식: (시도 시군구)? (동) (산)?(본번)(-(부번))?(번지|호)
   "호"와 "번지" 모두 지번 종결어로 인정
   실패 시 SKIP + 사유 카운트(EMPTY / NO_DONG_MATCH / UNPARSEABLE)

4. 동 이름 → legaldong_codes.csv 룩업 → 법정동코드(10자리)
   매칭 실패 시 SKIP + 사유 카운트(DONG_NOT_FOUND)

5. PNU 조립: 법정동코드(10) + 산여부(1: "산"이면 1, 아니면 0) + 본번(4, zero-pad) + 부번(4, zero-pad)
   = 19자리

6. 상태 매핑: 이 파일 전용 (상세영업상태코드 → 상세영업상태명) → 기존 5버킷
   (영업/정상, 폐업, 휴업, 취소/말소/만료/정지/중지, 제외/삭제/전출)
   파일마다 코드 사전이 다르므로 매핑 테이블은 파일 단위로 새로 작성 — 공용 매핑 없음

7. 좌표: 원본 X/Y 값 그대로 저장 (변환 안 함)

8. SQL INSERT 청크 생성
   기존 `src/main/resources/data/licensed-business-records-NNN.sql`과 동일 포맷
   기존 최대 id/파일 번호 다음부터 이어붙임
```

### 스킵 정책

PNU 유도 실패(동 매칭 실패/잡텍스트 지번/공백)는 해당 레코드만 드롭. 스크립트 실행 끝에 사유별 카운트를 요약 출력한다(예: `SKIP EMPTY: 301, SKIP UNPARSEABLE: 196, SKIP DONG_NOT_FOUND: N`). 기존 `COORD_CONVERT_FAIL` 로그-후-제외 패턴과 동일한 철학 — 실패를 조용히 삼키지 않는다.

### 확장성

파일마다 원본 컬럼·상태코드 사전이 다르므로 범용 플러그인 아키텍처는 만들지 않는다(YAGNI). 이번엔 "LOCALDATA 표준 24컬럼 포맷" 하나를 처리하는 스크립트로 시작하고, 구조가 다른 파일이 추가되면 그때 필요한 만큼만 확장한다.

## 테스트 시나리오

1. **정상 지번(번지)**: `경기도 성남시 수정구 태평동 2254` → 법정동코드+본번=2254+부번=0000
2. **구식 지번(호)**: `경기도 성남시수정구 수진동 4355호` → `4224번지`와 동일하게 파싱(공백 유무·종결어 무관)
3. **본번-부번 조합**: `수진동 2679-20호` → 본번=2679, 부번=0020
4. **산 표기**: `복정동 산65-1...` → 산여부=1, 본번=0065, 부번=0001
5. **매칭 실패**: 잡텍스트(`...(1층)호`, 건물명 포함 등) → SKIP, UNPARSEABLE 카운트 증가
6. **동 이름 불일치**: 법정동코드 테이블에 없는 동 → SKIP, DONG_NOT_FOUND 카운트 증가
7. **상태 매핑**: `상세영업상태코드=2, 상세영업상태명=폐업처리` → 영업상태명 컬럼(`영업상태명`)을 우선 신뢰(이미 5버킷 값으로 원본에 존재 확인됨 — `영업/정상`, `폐업` 등), 상세코드는 보조 검증용
